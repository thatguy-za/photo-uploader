# Photo Uploader

A tiny self-hosted server (Node 24, SQLite, ~4 dependencies) with an installable PWA for uploading full-resolution photos and videos into folders on your server.

- **Admin**: the first person to register on a fresh install becomes the admin (the *owner*), so open the site and create your account straight after starting the container. The admin manages users and per-folder permissions. When adding a user the admin picks the type: **Standard** (folder access chosen per folder) or **Admin** (full access, can manage users). The owner can't be demoted or deleted, and nobody can demote or delete themselves, so there is always an admin. Standard users never see the admin UI.
- **Permissions** per user, per folder: *No access*, *Read*, or *Read & upload*.
- **Gallery**: a Google Photos / Immich-style timeline grouped by day, an Albums view over your folders, and a full-screen viewer (swipe / arrow keys, download original). Users only see folders they have access to.
- **Uploads** keep the original full-resolution file. The user picks the folder, and optionally a sub-folder (or creates one). Name clashes become `IMG_1.jpg`, `IMG_1 (1).jpg`; nothing is overwritten.
- **HEIC → JPG**: uploaded `.heic`/`.heif` files are converted to JPEG on the server (quality 92, EXIF and rotation kept) and the HEIC is discarded. If conversion ever fails, the HEIC is kept and the uploader is told.
- **Dates**: the "date taken" is the EXIF date, else the phone's file date, else the upload time. It is stored as the file's modified time, which the timeline sorts by.
- **Thumbnails** are generated on first view (sharp) and cached in `/appdata/thumbs`; safe to delete, they regenerate. Videos play from the original file; their grid tile is the first frame from the browser.
- **Per-user API token** for the iOS Shortcut and scripts.

## Run

```yaml
services:
  photo-uploader:
    image: ghcr.io/thatguy-za/photo-uploader:latest
    restart: unless-stopped
    environment:
      PUID: 1000
      PGID: 1000
    volumes:
      - ./photos:/data
      - ./appdata:/appdata
    ports: ["8080:8080"]
```

- Every sub-folder of `/data` is an uploadable folder. Map several: `- /mnt/family:/data/Family`, `- /mnt/work:/data/Work`.
- `PUID`/`PGID` must be able to **write** to those folders. `/data` is never chown'd; only `/appdata` is.
- First start: browse to the site and create the admin account. Registration is only open while no users exist; after that, only the admin can add users. (If the server is exposed to the internet before you do this, anyone who gets there first becomes admin, so register right away.)
- `/appdata` holds the SQLite database (back it up) and the thumbnail cache (disposable, `thumbs/`).
- Plain HTTP on port 8080; put your HTTPS reverse proxy in front (`X-Forwarded-Proto` is honoured so cookies are marked `Secure`). HTTPS is required for installing the PWA.
- Large uploads: set the proxy's body-size limit and timeouts high (e.g. nginx `client_max_body_size 0; proxy_request_buffering off;`).

## Using it

**Android** – open the site in Chrome → menu → *Install app*. In the gallery select photos → *Share* → *Photos*. The app opens, you pick the folder, tap Upload.

**iPhone** – iOS does not let web apps appear in the share sheet, so:
1. Add to Home Screen from Safari (Share → *Add to Home Screen*) and use *Choose photos / videos* in the app, **or**
2. Install the ready-made Shortcut: avatar → *Account* → generate an API token → *Download Shortcut* on the iPhone → *Add Shortcut*, then enter your server address and paste the token. After that: Photos → select any number of photos → Share → *Upload to server* → pick the folder. This is the closest iOS gets to "share from the gallery". (The Shortcut sends one request per photo, so batches of any size work.)

   The signed file lives at `public/Upload-to-server.shortcut` and is generated by `shortcuts/build.py` (macOS only: `python3 shortcuts/build.py unsigned.shortcut && shortcuts sign -m anyone -i unsigned.shortcut -o public/Upload-to-server.shortcut`).

**Scripts**
```bash
curl -H "Authorization: Bearer pu_XXXX" -F file=@IMG_0001.jpg "https://photos.example.com/api/upload?folder=Family/Holiday"
curl -H "Authorization: Bearer pu_XXXX" --data-binary @IMG_0002.heic "https://photos.example.com/api/upload?folder=Family/Holiday&name=IMG_0002.heic"   # raw body, one file
curl -H "Authorization: Bearer pu_XXXX" https://photos.example.com/api/targets   # folders you may upload to
```

## Releasing

Publishing a GitHub release runs `.github/workflows/release.yml`, which builds `linux/amd64` + `linux/arm64` and pushes `ghcr.io/<owner>/<repo>` tagged `X.Y.Z`, `X.Y` and `latest`. Tag releases as `vX.Y.Z`. (First push: make the package public under the repo's *Packages* settings if you want unauthenticated pulls.)

## Develop

```bash
npm install
DATA_DIR=./photos APPDATA_DIR=./appdata PORT=8080 npm start
```
